### 1.1 วัตถุประสงค์การเรียนรู้ (Learning Objectives — ตาม Bloom’s Revised Taxonomy)

เมื่อเรียนจบบทเรียนนี้ นักศึกษาจะสามารถ:

1.  **(Remember)** ระบุความสามารถและข้อจำกัดของ Wokwi Simulator
    รวมถึงหน้าที่ของไฟล์ \`wokwi.toml\` และ \`diagram.json\` ในโปรเจกต์ได้

2.  **(Understand)**
    อธิบายความแตกต่างระหว่างการจำลองผ่านเว็บเบราว์เซอร์กับการคอมไพล์บนเครื่องแล้วจำลองผ่าน
    VS Code รวมถึงบทบาทของ Arduino CLI และ PlatformIO Core ได้

3.  **(Apply)** ติดตั้ง Wokwi Extension ขอ License Key และคอมไพล์โปรเจกต์
    Arduino ด้วย \`arduino-cli\` หรือ \`pio\` จนจำลองการทำงานสำเร็จได้

4.  **(Analyze)** วิเคราะห์ข้อความผิดพลาด (error/warning)
    จากคอมไพเลอร์และผลการจำลอง เพื่อระบุสาเหตุที่แท้จริงของปัญหาได้

5.  **(Evaluate)** ประเมินความถูกต้องของโค้ดและวงจรที่ได้จาก Generative AI
    เทียบกับเอกสารข้อกำหนดของอุปกรณ์ (datasheet) และผลการจำลองจริงได้

6.  **(Create)** ออกแบบและสร้างโปรเจกต์ต้นฉบับที่ประกอบด้วยไฟล์
    \`diagram.json\`, \`wokwi.toml\`, ซอร์สโค้ด และไฟล์ตั้งค่าการคอมไพล์
    พร้อมสาธิตการทำงานได้

## ส่วนที่ 2: บทนำ — ทำไมต้องจำลองก่อนต่อวงจรจริง

การเรียนรู้ระบบสมองกลฝังตัว (Embedded Systems) และ IoT
ตามปกติต้องอาศัยฮาร์ดแวร์จริง ซึ่งสร้างอุปสรรคหลายด้านต่อผู้เรียน ได้แก่ **ต้นทุนอุปกรณ์**,
**ความเสี่ยงที่อุปกรณ์เสียหาย** จากการต่อวงจรผิด, และ **ข้อจำกัดด้านเวลาและสถานที่**
เพราะต้องอยู่ในห้องปฏิบัติการเท่านั้น เครื่องมือจำลอง (Simulator) จึงเข้ามาเติมช่องว่างนี้
โดยให้ผู้เรียนทดลองตรรกะของโปรแกรมและการเชื่อมต่อวงจรได้ทุกที่ทุกเวลา
ก่อนนำไปทดสอบกับอุปกรณ์จริง

บทเรียนนี้เน้นรูปแบบการทำงานที่ต่างจากการใช้ Wokwi ผ่านเว็บเบราว์เซอร์ทั่วไป นั่นคือการใช้
**VS Code IDE เป็นศูนย์กลางการพัฒนา** โดย **คอมไพล์โค้ดบนเครื่องของผู้เรียนเอง**
ด้วยเครื่องมือมาตรฐานอุตสาหกรรม (Arduino CLI, PlatformIO, GCC-AVR)
แล้วส่งเฉพาะไฟล์เฟิร์มแวร์ที่ได้ไปให้ Wokwi จำลองการทำงาน
วิธีนี้ให้ประโยชน์สามข้อที่สำคัญต่อการเรียนวิชาชีพ:

- **ความเร็ว —** ไม่ต้องรอคิวคอมไพล์บนเซิร์ฟเวอร์
  การแก้โค้ดแล้วทดสอบซ้ำจึงทำได้เร็วกว่ามาก

- **เครื่องมือมืออาชีพ —** ผู้เรียนได้ฝึกใช้ Git, Terminal, ระบบจัดการไลบรารี และ
  toolchain ชุดเดียวกับที่ใช้ในงานจริง ไม่ใช่เฉพาะหน้าเว็บสำเร็จรูป

- **การควบคุมโปรเจกต์ —** โครงสร้างไฟล์ทั้งหมดอยู่ในเครื่อง จึงบริหารเวอร์ชันด้วย Git
  และส่งงานเป็นรีโพซิทอรีได้

| **เอกสารนี้เรียบเรียงจาก:** บทความ "แนะนำการใช้งาน VS Code IDE + Wokwi" จากเว็บไซต์ IoT Engineering Education (iot-kmutnb.github.io) ซึ่งเผยแพร่ภายใต้สัญญาอนุญาต Creative Commons Attribution-ShareAlike 4.0 International โดยผู้สอนได้ขยายเนื้อหา ปรับปรุงข้อมูลเวอร์ชันให้เป็นปัจจุบัน (สิงหาคม 2026) และเพิ่มองค์ประกอบการเรียนการสอน |

## ส่วนที่ 3: รู้จัก Wokwi Simulator

### 3.1 Wokwi คืออะไร

Wokwi เป็นซอฟต์แวร์ประเภท Web Application
สำหรับเขียนโค้ดและจำลองการทำงานของไมโครคอนโทรลเลอร์
ทำงานผ่านเว็บเบราว์เซอร์โดยตรงโดยผู้ใช้ไม่ต้องติดตั้งโปรแกรมลงเครื่อง เริ่มพัฒนาในปี ค.ศ.
2019 โดย **Uri Shaked** นักพัฒนาซอฟต์แวร์ชาวอิสราเอล
จุดประสงค์หลักคือให้ผู้ใช้ทดสอบและพัฒนาโค้ดได้โดยไม่ต้องมีฮาร์ดแวร์จริง
จึงเหมาะกับการเรียนรู้และฝึกเขียนโปรแกรมไมโครคอนโทรลเลอร์ในเบื้องต้น

## ส่วนที่ 4: การติดตั้งและตั้งค่า Wokwi Extension บน VS Code

### 4.1 ขั้นตอนการติดตั้ง

1.  **ติดตั้ง VS Code —** ดาวน์โหลด Visual Studio Code จากเว็บไซต์ทางการของ
    Microsoft และติดตั้งให้เรียบร้อยก่อน

2.  **เปิดใช้งาน VS Code —** กรณีใช้ Ubuntu โดยตรง เปิดจากเมนูแอปพลิเคชัน
    หรือพิมพ์คำสั่ง \`code\` ใน Terminal

3.  **กรณีใช้ WSL2 Ubuntu บน Windows —** เปิด VS Code ในโหมด Remote - WSL
    เพื่อให้เชื่อมต่อกับสภาพแวดล้อม Ubuntu โดยตรง ส่วนขยายและ toolchain
    ทั้งหมดจะถูกติดตั้งฝั่ง Ubuntu

4.  **ค้นหาและติดตั้ง Wokwi Extension —** ในแถบ Extensions ค้นหาคำว่า "Wokwi
    Simulator" แล้วกดติดตั้ง

5.  **ขอ License Key —** กด F1 (หรือ Ctrl+Shift+P) แล้วเลือกคำสั่ง "Wokwi:
    Request a new License" ระบบจะเปิดเว็บเบราว์เซอร์ให้ยืนยัน จากนั้นกดปุ่มขอ
    License และอนุญาตให้ส่งกลับเข้า VS Code เมื่อสำเร็จจะขึ้นข้อความยืนยันการเปิดใช้งาน

หากเบราว์เซอร์ไม่ส่ง License กลับให้อัตโนมัติ ให้คัดลอกคีย์ที่แสดงบนหน้าเว็บ แล้วใช้คำสั่ง
Wokwi: Manually Enter License Key ใน Command Palette เพื่อวางคีย์เอง
ทำเพียงครั้งเดียวต่อเครื่อง

| **ข้อควรทราบเรื่องอายุ License:** แหล่งข้อมูลต่าง ๆ ระบุอายุของ License ฟรีไม่ตรงกัน (บางแหล่งระบุ 30 วัน บางแหล่งระบุ 1 ปี) และเงื่อนไขอาจเปลี่ยนแปลงได้ ให้ตรวจสอบวันหมดอายุจริงจากหน้า wokwi.com/license และแนะนำนักศึกษาว่าเมื่อหมดอายุสามารถขอใหม่ได้ฟรีด้วยขั้นตอนเดิม |
|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|

## ส่วนที่ 5: โครงสร้างโปรเจกต์และไฟล์ตั้งค่าสำคัญ

โปรเจกต์ Wokwi ที่ทำงานบน VS Code ต้องมีไฟล์ตั้งค่าสองไฟล์เป็นอย่างน้อย
ซึ่งเป็นหัวใจของบทเรียนนี้

### 5.1 ไฟล์ wokwi.toml — บอกว่าเฟิร์มแวร์อยู่ที่ไหน

ไฟล์นี้ใช้ตั้งค่าการทำงานร่วมกับ Wokwi Simulator โดยระบุตำแหน่งไฟล์ .hex หรือ .bin
และไฟล์ .elf ที่ได้จากการคอมไพล์ ตำแหน่งไฟล์จะต่างกันตามเครื่องมือที่ใช้ ดังตาราง

| **เครื่องมือคอมไพล์**  | **ค่าที่ต้องระบุใน wokwi.toml**                                                                                     |
|--------------------|----------------------------------------------------------------------------------------------------------------|
| arduino-cli (Uno)  | firmware = ‘build/arduino.avr.uno/\<ชื่อโปรเจกต์\>.ino.hex’ · elf = ‘build/arduino.avr.uno/\<ชื่อโปรเจกต์\>.ino.elf’ |
| PlatformIO (Uno)   | firmware = ‘.pio/build/uno/firmware.hex’ · elf = ‘.pio/build/uno/firmware.elf’                                 |
| PlatformIO (ESP32) | firmware = ‘.pio/build/esp32dev/firmware.bin’ · elf = ‘.pio/build/esp32dev/firmware.elf’                       |
| avr-gcc (AVR LibC) | firmware = ‘build/main.hex’ · elf = ‘build/main.elf’                                                           |

**สังเกตความแตกต่าง:** บอร์ดตระกูล AVR ใช้ไฟล์ .hex ส่วน ESP32 ใช้ .bin และไฟล์
.elf จำเป็นสำหรับการดีบัก (แสดงชื่อฟังก์ชันและตัวแปร) —

## ส่วนที่ 10: การบูรณาการ Generative AI ในงานพัฒนาระบบฝังตัว

### 10.1 หลักคิด: AI เป็นผู้ช่วยดีบัก ไม่ใช่ผู้เขียนแทน

งานระบบฝังตัวมีลักษณะเฉพาะที่ทำให้ต้องระวังการใช้ AI มากกว่างานซอฟต์แวร์ทั่วไป เพราะ
**โค้ดที่ "ดูเหมือนถูก" อาจทำให้ฮาร์ดแวร์จริงเสียหายได้** เช่น
การตั้งค่าขาเป็นเอาต์พุตแล้วต่อเข้ากับแหล่งจ่ายไฟ หรือการดึงกระแสเกินพิกัดของขา
นอกจากนี้โมเดล AI มักสับสนระหว่างชิปตระกูลต่าง ๆ (เช่น ใช้ชื่อรีจิสเตอร์ของ ATmega328P
กับ ESP32) ดังนั้นแนวทางในรายวิชานี้คือ

- **ให้ AI อธิบาย ไม่ใช่ให้ AI เขียน —** ใช้ AI แปลความหมายของ error message
  และอธิบายว่ารีจิสเตอร์แต่ละบิตทำอะไร

- **ตรวจสอบกับ datasheet เสมอ —** ทุกคำตอบที่เกี่ยวกับรีจิสเตอร์ ขา หรือค่าไฟฟ้า
  ต้องยืนยันกับเอกสารทางการของผู้ผลิต

- **ทดสอบในตัวจำลองก่อนเสมอ —** Wokwi
  ทำหน้าที่เป็นด่านตรวจสอบชั้นแรกที่ไม่มีต้นทุนความเสียหาย

## ส่วนที่ 13: แบบฝึกหัด/คำถามท้ายบท (พร้อมแนวคำตอบ)

### 13.1 คำถามทบทวน

1.  **ไฟล์ wokwi.toml และ diagram.json ทำหน้าที่ต่างกันอย่างไร?** แนวตอบ:
    wokwi.toml ระบุตำแหน่งไฟล์เฟิร์มแวร์ (.hex/.bin) และ .elf ที่ได้จากการคอมไพล์
    ส่วน diagram.json อธิบายวงจร คือรายการอุปกรณ์และการเชื่อมต่อระหว่างขา

2.  **เมื่อใช้ Wokwi ผ่าน VS Code การคอมไพล์และการจำลองเกิดขึ้นที่ใด?** แนวตอบ:
    คอมไพล์เกิดบนเครื่องผู้ใช้ด้วย toolchain ที่ติดตั้งเอง
    ส่วนการจำลองยังทำงานผ่านบริการของ Wokwi จึงต้องเชื่อมต่ออินเทอร์เน็ต

3.  **เหตุใดบอร์ด Uno ใช้ไฟล์ .hex แต่ ESP32 ใช้ .bin?** แนวตอบ:
    เป็นรูปแบบไฟล์เฟิร์มแวร์ตามสถาปัตยกรรมและ toolchain ของแต่ละตระกูลชิป — AVR ใช้
    Intel HEX ส่วน ESP32 ใช้ไบนารีที่มีโครงสร้างพาร์ทิชันของตนเอง ส่วนไฟล์ .elf
    ใช้ประกอบการดีบักทั้งสองกรณี

4.  **พารามิเตอร์ --fqbn ในคำสั่ง arduino-cli compile หมายถึงอะไร ยกตัวอย่าง 1
    ค่า** แนวตอบ: Fully Qualified Board Name คือชื่อบอร์ดเป้าหมายในรูปแบบ
    ผู้ผลิต:สถาปัตยกรรม:รุ่น เช่น arduino:avr:uno

5.  **เปรียบเทียบข้อดีของ arduino-cli กับ PlatformIO มาอย่างละ 1 ข้อ** แนวตอบ:
    arduino-cli ติดตั้งง่ายและเหมาะกับ Arduino Sketch เดิม; PlatformIO
    จัดการหลายบอร์ด/หลายเฟรมเวิร์ก และประกาศไลบรารีในไฟล์ platformio.ini
    ทำให้ทำซ้ำสภาพแวดล้อมได้

6.  **เหตุใด vTaskDelay() จึงเหมาะกว่า delay() ในโปรแกรม FreeRTOS?**
    แนวตอบ: vTaskDelay() คืนเวลาประมวลผลให้ทาสก์อื่นระหว่างรอ
    ทำให้ทาสก์ทำงานคู่ขนานได้จริง ขณะที่ delay() ยึดครองการทำงานไว้

7.  **ยกข้อจำกัดของการทดสอบด้วย Simulator มา 2 ข้อ** แนวตอบ:
    ฮาร์ดแวร์บางส่วนอาจยังไม่รองรับหรือไม่ครอบคลุมทั้งหมด
    และตัวจำลองไม่สะท้อนปัจจัยทางกายภาพ เช่น สัญญาณรบกวน กระแสจริงที่อุปกรณ์ดึง
    หรือปัญหาการต่อกราวด์

8.  **(วิเคราะห์)** นักศึกษาคอมไพล์สำเร็จแต่กดจำลองแล้ว Wokwi
    แจ้งว่าไม่พบไฟล์เฟิร์มแวร์ จงระบุสาเหตุที่เป็นไปได้ 3 ข้อ พร้อมวิธีตรวจสอบทีละข้อ
    แนวตอบ: (1) พาธใน wokwi.toml ไม่ตรงกับ --output-dir
    ตรวจโดยเทียบชื่อโฟลเดอร์จริง (2) ชื่อไฟล์ผลลัพธ์ไม่ตรง เพราะ arduino-cli
    ตั้งชื่อตามชื่อโฟลเดอร์โปรเจกต์ (3) คอมไพล์ไม่สำเร็จจริงแต่มองข้าม error
    ตรวจโดยดูรหัสสถานะและอ่านบรรทัดสุดท้ายของผลลัพธ์
