## แนวคำตอบข้อ 11

**11.1** Wokwi ไม่รองรับ ESP8266 จึงต้องใช้ ESP32 แทน ผลต่อโค้ดมีน้อยมากเพราะยังใช้ Arduino framework และฟังก์ชันชุดเดียวกัน (`pinMode`, `digitalRead`, `digitalWrite`) สิ่งที่ต่างคือ (1) ไม่มีมาโคร `D0`–`D8` แบบ NodeMCU ต้องอ้างหมายเลข GPIO ตรง ๆ (2) ตำแหน่งขาบนบอร์ดต่างกัน ต้องดูตารางเทียบขา (3) ถ้าใช้ WiFi ต้อง `#include <WiFi.h>` แทน `<ESP8266WiFi.h>`

**11.2** `diagram.json` = วงจร (มีอุปกรณ์อะไร ต่อสายอย่างไร) · `wokwi.toml` = บอกว่าไฟล์เฟิร์มแวร์ที่คอมไพล์แล้วอยู่ที่พาธใด ถ้าขาดไฟล์ใดไฟล์หนึ่ง ส่วนขยาย Wokwi จะไม่เริ่มการจำลอง — ขาด `wokwi.toml` จะฟ้องว่าหาไฟล์คอนฟิกไม่พบ ขาด `diagram.json` จะไม่มีวงจรให้จำลอง

**11.3** เพราะขา OUT ของ PIR ถูกกำหนดให้คงสถานะ HIGH ไว้ตามค่า `delayTime` (ค่าปริยาย 5 วินาที) และโปรแกรมอ่านค่าซ้ำทุก 1 วินาที จึงพิมพ์ข้อความเดิมประมาณ 5 ครั้ง อีกทั้งโปรแกรมพิมพ์ทุกครั้งที่วนลูป ไม่ได้พิมพ์เฉพาะตอนสถานะเปลี่ยน (แก้ได้ในกิจกรรมข้อ 12.2)

**11.4** `COM` คือขาร่วมของหน้าสัมผัส · `NO` ปกติไม่ต่อกับ COM จะต่อเมื่อรีเลย์ทำงาน · `NC` ปกติต่อกับ COM อยู่แล้วและจะตัดเมื่อรีเลย์ทำงาน · ต้องใช้รีเลย์เพราะขา GPIO จ่ายกระแสได้เพียงระดับ 12–40 mA ที่ 3.3 V ไม่พอขับโหลดไฟฟ้า และรีเลย์ยังทำหน้าที่แยกวงจร (isolation) ป้องกันไฟแรงสูงย้อนเข้าไมโครคอนโทรลเลอร์

**11.5** ทำได้ 2 แนวทาง (นักศึกษาตอบทางใดทางหนึ่งก็ถือว่าถูก)
- แก้ที่วงจรจำลอง: ตั้งค่า `delayTime` ของ PIR เป็น `"10"`
- แก้ที่โปรแกรม: จับเวลาด้วย `millis()` แล้วให้หลอดติดค้างจนครบ 10,000 ms นับจากการตรวจพบครั้งล่าสุด (วิธีนี้ตรงกับพฤติกรรมที่ต้องการมากกว่า เพราะไม่ขึ้นกับตัวเซนเซอร์)

**11.6** ตัวอย่างคำตอบ — ข้อดี: ไม่ต้องมีอุปกรณ์จริง ทดลองซ้ำได้ไม่จำกัด ไม่มีความเสี่ยงจากไฟฟ้าแรงสูง แก้วงจรได้ทันที · ข้อจำกัด: ไม่เห็นปัญหาทางกายภาพ (สายหลวม กระแสไม่พอ สัญญาณรบกวน) เวลาตอบสนองไม่ตรงกับของจริงเสมอไป อุปกรณ์บางชนิดไม่มีในไลบรารีของโปรแกรมจำลอง และต้องใช้อินเทอร์เน็ต

## แนวคำตอบกิจกรรมต่อยอด

### 12.2 แสดงข้อความเฉพาะตอนสถานะเปลี่ยน

```cpp
int lastState = LOW;

void loop() {
  int state = digitalRead(sensor);
  if (state != lastState) {
    if (state == HIGH) Serial.println("Motion detected!");
    else               Serial.println("Motion ended!");
    digitalWrite(LED, state);
    digitalWrite(Status, state);
    lastState = state;
  }
}
```

### 12.3 เลิกใช้ delay() และหน่วงเวลาด้วย millis()

```cpp
const unsigned long HOLD_MS = 10000;   // ติดค้าง 10 วินาที
unsigned long lastMotion = 0;
bool lampOn = false;

void loop() {
  if (digitalRead(sensor) == HIGH) {
    lastMotion = millis();
    if (!lampOn) {
      lampOn = true;
      digitalWrite(LED, HIGH);
      digitalWrite(Status, HIGH);
      Serial.println("Motion detected!");
    }
  }

  if (lampOn && (millis() - lastMotion >= HOLD_MS)) {
    lampOn = false;
    digitalWrite(LED, LOW);
    digitalWrite(Status, LOW);
    Serial.println("Motion ended!");
  }
}
```

> จุดสอนสำคัญ: การเขียน `millis() - lastMotion >= HOLD_MS` ปลอดภัยกว่า `millis() >= lastMotion + HOLD_MS` เพราะทำงานถูกต้องแม้ค่า `millis()` วนกลับเป็นศูนย์ (ทุก ~49.7 วัน)

## ผลที่ควรได้ในตารางบันทึกผล (ข้อ 10)

| ครั้งที่ | STATUS | LAMP | Serial Monitor |
|---|---|---|---|
| 1 ก่อนกด | ดับ | ดับ | Motion absent! (ซ้ำทุก 1 วินาที) |
| 2 ทันทีที่กด | ติด | ติด | Motion detected! |
| 3 ผ่านไป 3 วินาที | ติด | ติด | Motion detected! (ยังอยู่ในช่วง delayTime) |
| 4 ผ่านไป 7 วินาที | ดับ | ดับ | Motion absent! (พ้น 5 วินาทีแล้ว) |
| 5 ตั้ง delayTime = 10 | ติดนานขึ้นเป็น 10 วินาที | เช่นเดียวกัน | Motion detected! ยาวขึ้น |
