# แนวคำตอบและหมายเหตุสำหรับอาจารย์ผู้สอน — ใบงานที่ 6 (ฉบับ Wokwi + VS Code)

คณะเทคโนโลยีสารสนเทศ มหาวิทยาลัยราชภัฏร้อยเอ็ด · จำนวน 90 นาที

---

## ข้อผิดพลาดที่พบในใบงานต้นฉบับ และการแก้ไข

| ประเด็น | ต้นฉบับ | ฉบับนี้ |
|---|---|---|
| จุดประสงค์ทั่วไป | เขียนว่า "โดยการตรวจจับ**การเคลื่อนไหว**" | แก้เป็นตรวจจับความเข้มแสง (ต้นฉบับคัดลอกมาจากใบงานที่ 5) |
| หัวข้อ 9 การทดสอบ | บรรยายว่า "ใช้มือเคลื่อนที่ผ่าน PIR Sensor สังเกตการทำงานของรีเลย์" | เขียนใหม่เป็นการปรับแถบ lux และปรับเทียบค่าเซนเซอร์ |
| เลขหัวข้อ | มี "8." ซ้ำสองครั้ง (ผังงาน / การเขียนโปรแกรม) | แยกเป็น 8 และ 9 |
| งานที่มอบหมาย | "เวลากลางวันให้ LED ทำงาน" และ "เวลากลาง**วัน**ให้ LED หยุดทำงาน" — ขัดแย้งกันเอง | แก้บรรทัดที่สองเป็นกลางวันหยุดทำงาน / กลางคืนทำงาน |
| ค่าเกณฑ์ | `sensorValue < 400` (สเกล 10 บิต) | ปรับสเกลเป็น 1600 (12 บิต) แล้วให้นักศึกษาปรับเทียบเอง |
| บอร์ด | NodeMCU (ESP8266) | ESP32 DevKit V1 — Wokwi ยังไม่รองรับ ESP8266 |
| Serial | 9600 | 115200 ให้ตรงกับ `monitor_speed` |
| คำสั่ง if | ไม่ใส่ปีกกา | ใส่ปีกกาครบทุกกรณี |

**ประเด็นสำคัญที่สุดของใบงานนี้:** ทิศทางของสัญญาณ ในโมดูล `wokwi-photoresistor-sensor` ตัวต้านทาน 10 kΩ อยู่ระหว่าง VCC กับ AO และ LDR อยู่ระหว่าง AO กับ GND ดังนั้น **มืด → ค่าที่อ่านได้มาก / สว่าง → ค่าที่อ่านได้น้อย** โปรแกรมต้นฉบับที่ใช้ `< THRESHOLD` จึงทำให้หลอดติดตอน **กลางวัน** ซึ่งตรงข้ามกับพฤติกรรมไฟถนน — ตั้งใจคงไว้เพื่อให้นักศึกษาค้นพบเองแล้วแก้ในข้อ 12.1

> หากใช้โมดูล LDR ตัวจริงที่ต่อสลับด้าน (LDR อยู่ฝั่ง VCC) ทิศทางจะกลับกันทันที จึงต้องย้ำว่า **ห้ามจำค่า ให้วัดเสมอ**

## แนวคำตอบข้อ 11

**11.1** ภายในโมดูลเป็นวงจรแบ่งแรงดัน โดย 10 kΩ อยู่ฝั่ง VCC และ LDR อยู่ฝั่งกราวด์ แรงดันที่ขา AO = VCC × R(LDR) / (R(LDR) + 10k) เมื่อแสงมากขึ้น ความต้านทานของ LDR ลดลง สัดส่วนแรงดันตกคร่อม LDR จึงลดลงตาม ค่าที่ `analogRead()` อ่านได้จึงลดลง

**11.2** ADC ของ ESP32 เป็น 12 บิต (0–4095) เกณฑ์ 400 จึงคิดเป็นเพียงประมาณร้อยละ 10 ของช่วงทั้งหมด (เทียบเท่าประมาณ 100 ในสเกล 10 บิต) ทำให้เงื่อนไข `< 400` เป็นจริงเฉพาะตอนแสงจ้ามาก ๆ เท่านั้น หลอดจึงแทบไม่ติดเลยในสภาพแสงปกติ

**11.3** ขา ADC ของ ESP32 รับแรงดันได้สูงสุด 3.3 V หากเลี้ยงโมดูลด้วย 5 V ตอนมืดแรงดันที่ขา AO จะขึ้นไปเกือบ 5 V ซึ่งเกินพิกัดและทำให้ขาสัญญาณเสียหายถาวร (ในโปรแกรมจำลองไม่พัง แต่จะพังบนบอร์ดจริง)

**11.4** ติดในเวลา **กลางวัน** เพราะกลางวันค่าที่อ่านได้น้อย จึงเข้าเงื่อนไข `<` แก้ได้โดยเปลี่ยนเครื่องหมายเป็น `>` (หรือสลับคำสั่งใน if กับ else)

**11.5** หลอดจะกระพริบถี่ ๆ (chattering) เมื่อค่าที่อ่านได้แกว่งข้ามเกณฑ์ไปมา ป้องกันได้ 2 วิธี — (1) ใช้ช่วงกันสั่นแบบฮีสเทอรีซิส คือกำหนดเกณฑ์เปิดกับเกณฑ์ปิดให้ต่างกัน เช่น เปิดที่ 1800 ปิดที่ 1400 (2) หน่วงเวลาให้สภาพแสงคงที่ครบตามกำหนดก่อนจึงสลับสถานะ ซึ่งเป็นวิธีที่ใช้ในข้อ 12.2

**11.6** ขา DO ข้อดีคือใช้ขาดิจิทัลธรรมดาได้ เขียนโปรแกรมง่าย ไม่ต้องปรับเทียบตัวเลข ข้อเสียคือได้ข้อมูลเพียงสองสถานะ ปรับเกณฑ์ได้เฉพาะที่ตัวโมดูล (บนของจริงต้องหมุนตัวต้านทานปรับค่า) และนำค่าไปคำนวณหรือบันทึกเป็นข้อมูลต่อไม่ได้

## แนวคำตอบงานที่มอบหมาย (ข้อ 12.1 + 12.2)

```cpp
#include <Arduino.h>

int sensorPin = A0;
const int LED_PIN = 13;
int THRESHOLD = 1600;                      // ปรับตามค่าที่วัดได้จริง

const unsigned long STABLE_MS = 180000UL;  // ต้องคงที่ครบ 3 นาที
int lampState    = LOW;                    // สถานะหลอดไฟจริง
int pendingState = LOW;                    // สถานะที่กำลังรอให้ครบเวลา
unsigned long pendingSince = 0;

void setup() {
  pinMode(LED_PIN, OUTPUT);
  Serial.begin(115200);
}

void loop() {
  int value = analogRead(sensorPin);

  // ค่ามาก = มืด -> ต้องการให้หลอดติด  (แก้เครื่องหมายจาก < เป็น > ตามข้อ 12.1)
  int desired = (value > THRESHOLD) ? HIGH : LOW;

  if (desired != pendingState) {           // สภาพแสงเพิ่งเปลี่ยน เริ่มจับเวลาใหม่
    pendingState = desired;
    pendingSince = millis();
  }

  if (desired != lampState && (millis() - pendingSince >= STABLE_MS)) {
    lampState = desired;                   // คงที่ครบ 3 นาทีแล้ว จึงสลับสถานะ
    digitalWrite(LED_PIN, lampState);
    Serial.println(lampState == HIGH ? "Lamp ON (night)" : "Lamp OFF (day)");
  }

  Serial.println(value);
  delay(500);
}
```

**จุดที่ควรตรวจในผลงานนักศึกษา**

1. เปลี่ยนเครื่องหมายเปรียบเทียบถูกทิศทางหรือไม่ (`>` ไม่ใช่ `<`)
2. ใช้ `millis()` จริง ไม่ใช่ `delay(180000)` — ถ้าใช้ `delay` ระบบจะค้างและอ่านเซนเซอร์ไม่ได้ตลอด 3 นาที
3. เขียนเงื่อนไขเวลาเป็น `millis() - pendingSince >= STABLE_MS` ไม่ใช่ `millis() >= pendingSince + STABLE_MS` (แบบหลังจะพลาดเมื่อค่า `millis()` วนกลับเป็นศูนย์ทุก ~49.7 วัน)
4. ตัวจับเวลาต้องรีเซ็ตเมื่อสภาพแสงเปลี่ยนกลับ ไม่ใช่จับเวลาต่อเนื่องอย่างเดียว

> **เคล็ดลับตอนสาธิตในคาบ:** 3 นาทีนานเกินกว่าจะรอในห้องเรียน ให้นักศึกษาตั้ง `STABLE_MS` เป็น 5000 (5 วินาที) ตอนทดสอบ แล้วค่อยเปลี่ยนกลับเป็น 180000 ก่อนส่งงาน พร้อมเขียนหมายเหตุกำกับไว้

## ข้อ 12.3 (เลือกทำเพิ่ม) การใช้ขา DO

เพิ่มสายจาก `ldr1:DO` ไปยัง `esp:D14` แล้วอ่านด้วย `digitalRead(14)` — ขา DO จะเป็น HIGH เมื่อมืด และ LOW เมื่อสว่าง โดยเกณฑ์ตัดสินกำหนดจาก attribute `threshold` (ค่าปริยาย 2.5 V ≈ 100 lux) ให้เทียบกับผลจากขา AO ว่าเปลี่ยนสถานะที่ระดับแสงเดียวกันหรือไม่

## หมายเหตุเรื่องค่าที่วัดได้ในตารางข้อ 10

ค่าที่นักศึกษาอ่านได้จะ **ไล่จากมากไปน้อยเมื่อความสว่างเพิ่มขึ้น** สิ่งที่ต้องตรวจคือแนวโน้มและลำดับ ไม่ใช่ตัวเลขเป๊ะ ๆ เพราะขึ้นกับวิธีจำลอง ADC ของ Wokwi และแรงดันเลี้ยงที่ใช้ ถ้านักศึกษากลุ่มใดได้แนวโน้มกลับด้าน ให้ตรวจว่าต่อขา AO กับ VCC สลับกันหรือไม่

เกณฑ์ที่เหมาะสมคือค่ากึ่งกลางระหว่างค่าที่อ่านได้ตอน 10 lux (โพล้เพล้) กับตอน 1,000 lux (ฟ้าครึ้ม) เพราะเป็นช่วงรอยต่อกลางวัน-กลางคืนตามจริง

## การจัดคาบ 90 นาที

| ช่วงเวลา | กิจกรรม |
|---|---|
| 0–15 | ทบทวน LDR + วงจรแบ่งแรงดัน + ทิศทางของค่าที่อ่านได้ |
| 15–35 | สร้างโปรเจกต์และวางวงจรใน `diagram.json` |
| 35–50 | เขียนโค้ด คอมไพล์ และรันจำลอง |
| 50–70 | ปรับเทียบค่าเซนเซอร์ 6 ระดับ + คำนวณ THRESHOLD |
| 70–80 | งานที่มอบหมายข้อ 12.1 (แก้เครื่องหมาย) และเริ่มข้อ 12.2 |
| 80–90 | เฉลยร่วมกัน สรุปผล ส่งงาน |

ถ้าเวลาไม่พอ ให้ข้อ 12.2 เป็นการบ้าน แต่ **อย่าตัดขั้นตอนปรับเทียบในข้อ 10** เพราะเป็นแก่นของใบงานนี้
