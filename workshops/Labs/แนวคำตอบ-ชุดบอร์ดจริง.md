# แนวคำตอบและคู่มือเตรียมคาบสำหรับอาจารย์ — ชุดใบงานปฏิบัติบนบอร์ดจริง

คณะเทคโนโลยีสารสนเทศ มหาวิทยาลัยราชภัฏร้อยเอ็ด

ชุดนี้ประกอบด้วย ใบงานที่ 0 (ติดตั้งเครื่องมือ), ใบงานที่ 5 (PIR), ใบงานที่ 6 (LDR) และใบงานที่ 8 (MQ-2 + HC-SR04) ทุกใบงานใช้บอร์ด **NodeMCU 1.0 (ESP-12E)** จริง ร่วมกับ Arduino IDE

---

## ส่วนที่ 1 — เตรียมก่อนเปิดคาบ

### รายการที่ต้องเตรียมต่อ 1 สถานี

| ใบงาน | อุปกรณ์เพิ่มเติมนอกจากบอร์ดทดลอง |
|---|---|
| 0 | สาย Micro USB **ชนิดสายข้อมูล** (เตรียมสำรองอย่างน้อย 3 เส้นต่อห้อง) |
| 5 | — (ใช้บล็อกบนบอร์ดทั้งหมด) |
| 6 | ไฟฉายจากโทรศัพท์, ผ้าหรือกล่องทึบสำหรับบังแสง |
| 8 | ตัวต้านทาน 1 kΩ และ 2 kΩ อย่างละ 2 ตัว, ไฟแช็ก (ไม่จุดไฟ), ตลับเมตร, แผ่นกระดาษแข็ง, มัลติมิเตอร์ |

### สิ่งที่ต้องสั่งล่วงหน้า

ให้นักศึกษาทำ **ใบงานที่ 0 ให้จบก่อนเข้าคาบใบงานที่ 5** การติดตั้งแพ็กเกจ ESP8266 มีขนาดหลายร้อยเมกะไบต์ ถ้าติดตั้งพร้อมกันทั้งห้องจะใช้เวลาเกิน 20 นาทีและเน็ตล่ม ทางเลือกคือเตรียมโฟลเดอร์แพ็กเกจสำเร็จไว้ให้คัดลอกลง `C:\Users\<user>\AppData\Local\Arduino15\packages\`

### เตรียมสายไว้ล่วงหน้า

ปัญหาอันดับหนึ่งของคาบแรกคือ **สายชาร์จที่ไม่มีเส้นข้อมูล** อาการคือไฟบนบอร์ดติดแต่เมนู Port เลือกไม่ได้ ควรทดสอบสายทุกเส้นก่อนแจก แล้วติดสติกเกอร์กำกับไว้

## ส่วนที่ 2 — ใบงานที่ 0 : แนวคำตอบข้อ 11

**11.1** สายชาร์จต่อเฉพาะขา VBUS และ GND ส่วนสายข้อมูลต่อขา D+ และ D− ด้วย ตรวจสอบโดยเสียบแล้วดูว่าเครื่องแจ้งเตือนพบอุปกรณ์ใหม่หรือไม่ และดูใน Device Manager ว่ามีรายการ USB-SERIAL ปรากฏหรือไม่ ถ้าไฟบนบอร์ดติดแต่ไม่มีพอร์ต แสดงว่าเป็นสายชาร์จ

**11.2** เพราะ Arduino IDE รู้จักเฉพาะบอร์ดตระกูล AVR ของ Arduino เองตั้งแต่แรก การเพิ่ม URL เป็นการบอกตำแหน่งไฟล์ดัชนีแพ็กเกจของบุคคลที่สาม (ESP8266 Community) เพื่อให้ Boards Manager ไปดาวน์โหลดคอมไพเลอร์ ไลบรารีแกน และเครื่องมืออัปโหลดของ ESP8266 มาติดตั้งเพิ่ม

**11.3** active-LOW หมายถึงไฟติดเมื่อขาเป็นลอจิก LOW และดับเมื่อเป็น HIGH เพราะขั้วบวกของ LED ต่อกับไฟเลี้ยงและขั้วลบต่อกับขา GPIO ผลคือโปรแกรมต้องสั่ง `digitalWrite(LED_BUILTIN, LOW)` เพื่อให้ไฟติด ซึ่งกลับกับ LED ภายนอกที่ต่อแบบปกติ

**11.4** ชิป ESP8266 รับแรงดันที่ขา ADC ได้เพียง 0–1.0 V บอร์ด NodeMCU จึงมีวงจรแบ่งแรงดันบนบอร์ดขยายช่วงเป็น 0–3.3 V การป้อน 5 V จะเกินพิกัดและทำให้ขาเสียหายถาวร แก้ไขด้วยวงจรแบ่งแรงดันภายนอก เช่น 1 kΩ กับ 2 kΩ

**11.5** D3 (GPIO0) ถ้าเป็น LOW ขณะบูตจะทำให้บอร์ดเข้าโหมดโปรแกรมแทนการรันโปรแกรมปกติ · D4 (GPIO2) ต้องเป็น HIGH ขณะบูต และมี LED บนบอร์ดต่ออยู่ · D8 (GPIO15) ต้องเป็น LOW ขณะบูต ถ้ามีโหลดดึงขาขึ้นบอร์ดจะไม่เริ่มทำงาน ทั้งสามขาจึงไม่เหมาะกับการขับโหลดในการทดลอง

## ส่วนที่ 3 — ใบงานที่ 5 (PIR)

### ผลที่ควรได้

| เหตุการณ์ | LED 3 | รีเลย์ | Serial Monitor |
|---|---|---|---|
| ก่อนมีการเคลื่อนไหว | ดับ | ไม่มีเสียง | Motion absent! ซ้ำทุก 1 วินาที |
| มือเคลื่อนผ่าน | ติด | ได้ยินเสียงคลิก | Motion detected! |
| นิ่ง 5 วินาที | ยังติด | ยังทำงาน | Motion detected! (อยู่ในช่วง Time Delay) |
| นิ่ง 10 วินาที | ดับ (ขึ้นกับการปรับ) | คลิกกลับ | Motion absent! |

ค่า Time Delay จากโรงงานมักอยู่ที่ 5–8 วินาที ถ้ากลุ่มใดได้ผลต่างจากนี้มาก ให้ตรวจตัวต้านทานปรับค่าบนโมดูลก่อน อย่าเพิ่งโทษโปรแกรม

### แนวคำตอบข้อ 11

**11.1** PIR ต้องปรับสมดุลกับรังสีอินฟราเรดพื้นหลังของห้องก่อน ระหว่างนั้นขา O/P จะสวิตช์เองแบบสุ่ม ถ้าไม่รอ ผลการทดลองช่วงแรกจะอ่านไม่ได้และนักศึกษาจะสรุปผิดว่าโปรแกรมผิด

**11.2** ตัวหนึ่งปรับความไว (Sensitivity) คือระยะตรวจจับ อีกตัวปรับเวลาคงสถานะ HIGH (Time Delay) ทั้งสองเป็นการปรับที่ **ฮาร์ดแวร์** ซึ่งเปลี่ยนสัญญาณที่ส่งออกมาจริง ต่างจากการแก้ในโปรแกรมที่เป็นการตีความสัญญาณที่ได้รับมาแล้ว

**11.3** COM คือขาร่วมของหน้าสัมผัส · NO ปกติไม่ต่อกับ COM และจะต่อเมื่อรีเลย์ทำงาน · NC ปกติต่ออยู่แล้วและจะตัดเมื่อรีเลย์ทำงาน ต้องใช้รีเลย์เพราะขา GPIO จ่ายกระแสได้เพียงระดับ 12 mA ที่ 3.3 V ไม่พอขับโหลด และรีเลย์ยังแยกวงจร (isolation) ป้องกันไฟแรงสูงย้อนเข้าไมโครคอนโทรลเลอร์

**11.4** เพราะขา O/P ของ PIR ส่งสัญญาณระดับ 3.3V TTL อยู่แล้ว ซึ่งอยู่ในพิกัดของ NodeMCU พอดี ส่วนขา ECHO ของ HC-SR04 ส่งออกมาที่ 5V TTL ซึ่งเกินพิกัด จึงต้องแบ่งแรงดันก่อน

**11.5** ตัวอย่าง — บนบอร์ดจริงมีเวลาอุ่นเครื่องที่โปรแกรมจำลองไม่มี · มีการแจ้งเตือนผิดพลาดจากลมแอร์และแสงแดด · เวลาคงสถานะปรับที่ตัวต้านทานบนโมดูลได้ ไม่ใช่แก้ที่ค่าในไฟล์วงจร · ได้ยินเสียงคลิกของรีเลย์จริง

### แนวคำตอบงานที่มอบหมาย 10.2 และ 10.3

```cpp
// 10.2 แสดงข้อความเฉพาะตอนสถานะเปลี่ยน
int lastState = LOW;

void loop() {
  int state = digitalRead(sensor);
  if (state != lastState) {
    Serial.println(state == HIGH ? "Motion detected!" : "Motion ended!");
    digitalWrite(LED, state);
    digitalWrite(Status, state);
    lastState = state;
  }
}
```

```cpp
// 10.3 เลิกใช้ delay() และให้ติดค้าง 10 วินาทีนับจากการตรวจจับครั้งสุดท้าย
const unsigned long HOLD_MS = 10000;
unsigned long lastMotion = 0;
bool lampOn = false;

void loop() {
  if (digitalRead(sensor) == HIGH) {
    lastMotion = millis();
    if (!lampOn) {
      lampOn = true;
      digitalWrite(LED, HIGH);
      digitalWrite(Status, HIGH);
      Serial.println("Motion detected!");
    }
  }
  if (lampOn && (millis() - lastMotion >= HOLD_MS)) {
    lampOn = false;
    digitalWrite(LED, LOW);
    digitalWrite(Status, LOW);
    Serial.println("Motion ended!");
  }
}
```

> จุดตรวจ: ต้องเขียน `millis() - lastMotion >= HOLD_MS` ไม่ใช่ `millis() >= lastMotion + HOLD_MS` เพราะแบบหลังจะพลาดเมื่อค่า `millis()` วนกลับเป็นศูนย์ (ทุกประมาณ 49.7 วัน)

## ส่วนที่ 4 — ใบงานที่ 6 (LDR)

### ประเด็นที่ต้องย้ำมากที่สุด

ทิศทางของค่าที่อ่านได้ **ขึ้นกับตำแหน่งจัมเปอร์ N-T / P-T ของบล็อก LDR** ไม่ใช่ค่าตายตัว ใบงานจึงออกแบบให้นักศึกษา **วัดก่อน แล้วจึงเลือกเครื่องหมายเปรียบเทียบ** อย่าเฉลยทิศทางให้ก่อน ปล่อยให้ค้นพบจากตารางข้อ 9

ถ้าห้องเรียนมีบอร์ดหลายชุดที่ตั้งจัมเปอร์ไม่เหมือนกัน นั่นคือโอกาสสอนที่ดี ให้เปรียบเทียบผลระหว่างกลุ่มแล้วอธิบายว่าทำไมค่าจึงกลับทิศ

### ผลที่ควรได้ (อ้างอิงคร่าว ๆ ค่าจริงต่างกันตามห้อง)

ช่วงค่าที่อ่านได้ควรกว้างพอสมควรระหว่างมืดสนิทกับส่องไฟฉาย ถ้าค่าต่างกันน้อยกว่า 100 หน่วย แสดงว่าบังแสงไม่มิดหรือสายหลวม ให้แก้ก่อนคำนวณเกณฑ์

### แนวคำตอบข้อ 11

**11.1** ตอบตามผลจริงที่วัดได้ พร้อมอธิบายว่าถ้า LDR อยู่ฝั่งไฟเลี้ยง แสงมากจะทำให้ความต้านทานลดลง แรงดันตกคร่อม LDR น้อยลง แต่แรงดันที่จุดวัดสูงขึ้น ค่าที่อ่านได้จึงเพิ่ม และกลับกันถ้า LDR อยู่ฝั่งกราวด์

**11.2** เพราะค่าที่อ่านได้ขึ้นกับความเข้มแสงพื้นฐานของสถานที่ ตัว LDR แต่ละตัวที่คลาดเคลื่อนต่างกัน และแรงดันไฟเลี้ยงที่อาจไม่เท่ากัน การใช้ค่าตายตัวจะทำให้ระบบทำงานผิดเมื่อย้ายที่

**11.3** NodeMCU มีขาแอนะล็อกเพียงขาเดียว รับแรงดันได้ 0–3.3 V ความละเอียด 10 บิต ถ้าต้องอ่าน 3 เซนเซอร์ต้องใช้ชิปมัลติเพล็กเซอร์ เช่น CD4051 หรือ 74HC4051 หรือใช้ ADC ภายนอกแบบ I2C เช่น ADS1115

**11.4** หลอดจะกระพริบถี่ (chattering) ป้องกันด้วยฮีสเทอรีซิส (เกณฑ์เปิดกับเกณฑ์ปิดต่างกัน) หรือหน่วงเวลาให้สภาพแสงคงที่ครบกำหนดก่อนสลับสถานะ

**11.5** ตัวอย่าง — ค่าที่อ่านได้มีสัญญาณรบกวนแกว่งเล็กน้อยตลอดเวลา ซึ่งโปรแกรมจำลองไม่มี · ต้องปรับเทียบเองทุกครั้ง · ทิศทางของค่าขึ้นกับจัมเปอร์บนบอร์ด · แสงจากจอคอมพิวเตอร์และหลอดไฟในห้องมีผลต่อค่า

### แนวคำตอบงานที่มอบหมาย 10.1–10.3

```cpp
const unsigned long STABLE_MS = 180000UL;   // 3 นาที
int lampState = LOW, pendingState = LOW;
unsigned long pendingSince = 0;

void loop() {
  int value = analogRead(sensorPin);

  // เลือกเครื่องหมายตามทิศทางที่วัดได้จริงในข้อ 9
  // ถ้ามืดแล้วค่ามาก ใช้  (value > THRESHOLD)
  // ถ้ามืดแล้วค่าน้อย ใช้ (value < THRESHOLD)
  int desired = (value > THRESHOLD) ? HIGH : LOW;

  if (desired != pendingState) {
    pendingState = desired;
    pendingSince = millis();
  }
  if (desired != lampState && (millis() - pendingSince >= STABLE_MS)) {
    lampState = desired;
    digitalWrite(LED_PIN, lampState);
    Serial.println(lampState == HIGH ? "Lamp ON (night)" : "Lamp OFF (day)");
  }
  Serial.println(value);
  delay(500);
}
```

**เคล็ดลับตอนสาธิต:** 3 นาทีนานเกินกว่าจะรอในห้องเรียน ให้ตั้ง `STABLE_MS` เป็น 5000 ตอนทดสอบ แล้วเปลี่ยนกลับเป็น 180000 ก่อนส่งงาน พร้อมเขียนหมายเหตุกำกับ

**ข้อ 10.3 (ฮีสเทอรีซิส)** ตัวอย่างเกณฑ์เปิดที่ THRESHOLD + 25 และเกณฑ์ปิดที่ THRESHOLD − 25 แล้วให้เปรียบเทียบว่าวิธีใดตอบสนองไวกว่า และวิธีใดทนต่อเงาที่ผ่านมาชั่วครู่ได้ดีกว่า

## ส่วนที่ 5 — ใบงานที่ 8 (MQ-2 + HC-SR04)

### จุดที่ต้องตรวจก่อนอนุญาตให้จ่ายไฟ

1. วงจรแบ่งแรงดันของขา O/P (MQ-2) และขา ECHO (HC-SR04) ต่อครบและถูกทิศทาง
2. นักศึกษาวัดแรงดันที่จุดวัดด้วยมัลติมิเตอร์แล้วได้ประมาณ 3.3 V (ไม่เกิน 3.4 V)
3. กราวด์ของบล็อก POWER SUPPLY กับ NodeMCU ต่อถึงกัน (ถ้าลืม ค่าที่อ่านได้จะลอยและแกว่ง)
4. ไม่มีสายใดต่อ +5VDC เข้าขา A0 หรือขา D ใด ๆ โดยตรง

> ถ้ามีเวลาจำกัด ให้เตรียมวงจรแบ่งแรงดันบัดกรีสำเร็จไว้บนบอร์ดโปรโตแบบถอดได้ แล้วให้นักศึกษาวัดแรงดันยืนยันเองแทนการต่อเอง

### ผลที่ควรได้

**การทดลองที่ 1** ค่าฐานของอากาศสะอาดในห้องปกติมักอยู่ในช่วงต่ำถึงปานกลางของสเกล 0–1023 และจะพุ่งขึ้นชัดเจนเมื่อปล่อยแก๊สใกล้เซนเซอร์ สิ่งที่ต้องตรวจคือ **แนวโน้ม** และการที่ค่าค่อย ๆ ลดลงหลังหยุดปล่อยแก๊ส (ไม่ลดทันที) ไม่ใช่ตัวเลขตายตัว

**การทดลองที่ 2** ค่าที่วัดได้ควรใกล้เคียงระยะจริงโดยมีความคลาดเคลื่อนไม่กี่เซนติเมตร กรณีเอียงแผ่นสะท้อน 45 องศาจะได้ค่าผิดพลาดมากหรือวัดไม่ได้เลย เพราะคลื่นสะท้อนออกไปทางอื่นไม่กลับเข้าตัวรับ — นี่คือคำตอบของข้อ 9.3

### แนวคำตอบข้อ 9

**9.1** TRIG เป็นอินพุตของโมดูล รับสัญญาณ 3.3 V จาก NodeMCU ได้เพราะเกินระดับ logic HIGH ของโมดูลแล้ว ส่วน ECHO เป็นเอาต์พุตที่โมดูลขับออกมาที่ 5 V ซึ่งเกินพิกัด 3.3 V ของ NodeMCU จึงต้องแบ่งแรงดัน

**9.2** ความเร็วเสียงประมาณ 340 m/s คิดเป็นประมาณ 29 ไมโครวินาทีต่อเซนติเมตร จึงหารด้วย 29 เพื่อได้ระยะทาง และเวลาที่วัดได้เป็นระยะไป-กลับ จึงหารด้วย 2 อีกครั้ง (รวมเท่ากับหารด้วย 58)

**9.3** มุมตกกระทบเท่ากับมุมสะท้อน เมื่อแผ่นเอียง 45 องศา คลื่นจะสะท้อนออกไปด้านข้างแทนที่จะกลับมาที่ตัวรับ ทำให้ไม่มีพัลส์กลับมาหรือได้พัลส์จากการสะท้อนหลายทอดซึ่งยาวผิดปกติ

**9.4** ฮีทเตอร์ทำให้สารกึ่งตัวนำภายในร้อนถึงอุณหภูมิทำงานจึงจะทำปฏิกิริยากับแก๊สได้ ถ้ายังไม่ร้อนพอค่าที่อ่านได้จะไม่น่าเชื่อถือ ส่วนที่ค่าไม่กลับทันทีเพราะโมเลกุลแก๊สที่ดูดซับบนผิวสารต้องใช้เวลาคายออก และแก๊สยังตกค้างรอบตัวเซนเซอร์

**9.5** timeout ทำให้ `pulseIn()` เลิกรอเมื่อครบเวลาที่กำหนดแล้วคืนค่า 0 แทนที่จะค้างรอถึง 1 วินาทีตามค่าปริยาย ซึ่งทำให้ทั้งระบบไม่ตอบสนอง ค่า 30000 ไมโครวินาทีครอบคลุมระยะประมาณ 5 เมตร

**9.6** ตัวอย่าง — ต้องอุ่นฮีทเตอร์ก่อนวัด · ค่าไม่กลับสู่ค่าเดิมทันที · ค่าขึ้นกับอุณหภูมิและความชื้นของห้อง · ต้องมีวงจรแบ่งแรงดันที่โปรแกรมจำลองไม่ต้องมี · การวัดระยะคลาดเคลื่อนตามมุมและพื้นผิวของวัตถุ

### แนวคำตอบงานที่มอบหมาย 8.5 (เซนเซอร์ช่วยจอดรถ)

```cpp
const int pingPin = D1;    // TRIG
const int inPin   = D2;    // ECHO (ผ่านวงจรแบ่งแรงดัน)
const int LED     = D0;
const int BUZZER  = D6;    // ย้ายจาก D1 เพราะขานั้นใช้เป็น TRIG แล้ว

unsigned long lastBeep = 0;

long readCm() {
  digitalWrite(pingPin, LOW);  delayMicroseconds(2);
  digitalWrite(pingPin, HIGH); delayMicroseconds(10);
  digitalWrite(pingPin, LOW);
  long d = pulseIn(inPin, HIGH, 30000);
  return d / 29 / 2;
}

void loop() {
  long cm = readCm();
  unsigned long interval;

  if (cm == 0 || cm > 100) {        // วัดไม่ได้ หรือไกล -> ไม่เตือน
    digitalWrite(LED, LOW);
    interval = 0;
  } else if (cm >= 20) {
    digitalWrite(LED, HIGH);
    interval = 600;
  } else {
    digitalWrite(LED, HIGH);
    interval = 120;
  }

  if (interval > 0 && millis() - lastBeep >= interval) {
    lastBeep = millis();
    tone(BUZZER, 2000, 60);
  }
  delay(50);
}
```

**กับดักที่นักศึกษาส่วนใหญ่พลาด** คือลืมแยกกรณี `pulseIn()` คืนค่า 0 ออกจากกรณี "ใกล้มาก" ทำให้บัซเซอร์ร้องถี่ตลอดเวลาเมื่อไม่มีวัตถุอยู่ข้างหน้า ให้ตรวจข้อนี้เป็นอันดับแรก

## ส่วนที่ 6 — การไล่ปัญหาในคาบอย่างรวดเร็ว

เรียงตามความถี่ที่พบจริง ให้ไล่ตามลำดับนี้ก่อนเสมอ

1. **ไม่เห็นพอร์ต** → เปลี่ยนสาย USB เป็นสายข้อมูล → ติดตั้งไดรเวอร์ CH340/CP210x → เปลี่ยนพอร์ต USB
2. **อัปโหลดไม่ผ่าน** → ปิด Serial Monitor ก่อน → ตรวจว่าเลือก Board เป็น NodeMCU 1.0 → กด FLASH ค้างแล้วแตะ RST
3. **Serial เป็นตัวอักษรเพี้ยน** → ตั้ง Serial Monitor เป็น 115200
4. **เซนเซอร์ไม่ตอบสนอง** → ตรวจกราวด์ร่วมก่อนเสมอ (สาเหตุอันดับหนึ่ง) → แล้วจึงตรวจขาสัญญาณ
5. **บอร์ดรีสตาร์ตเอง** → ไฟจาก USB ไม่พอ ให้จ่ายไฟบอร์ดทดลองจากอะแดปเตอร์ภายนอก
6. **ค่าแอนะล็อกแกว่งหรือลอย** → กราวด์ไม่ร่วมกัน หรือสายหลวม

## ส่วนที่ 8 — การเชื่อมโยงกับชุดใบงาน Wokwi

ชุดนี้ใช้คู่กับชุด Wokwi ที่ทำไว้ก่อนหน้าได้โดยตรง แนะนำลำดับการสอน

1. ให้ทำฉบับ Wokwi ก่อน เพื่อให้เข้าใจตรรกะของโปรแกรมโดยไม่ติดปัญหาฮาร์ดแวร์
2. แล้วจึงทำฉบับบอร์ดจริง โดยใช้คำถามข้อสุดท้ายของทุกใบงาน ("ระบุความแตกต่างระหว่างโปรแกรมจำลองกับบอร์ดจริง") เป็นตัวเชื่อมการเรียนรู้ทั้งสองส่วนเข้าด้วยกัน

ความแตกต่างที่ควรสรุปร่วมกันในคาบสุดท้าย ได้แก่ เวลาอุ่นเครื่องของเซนเซอร์ สัญญาณรบกวน ความคลาดเคลื่อนของการวัด ข้อจำกัดเรื่องแรงดัน และการที่ฮาร์ดแวร์บางอย่างปรับที่ตัวอุปกรณ์ไม่ใช่ที่โปรแกรม
